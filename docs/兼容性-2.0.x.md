# SlashBlade 2.0.7 兼容性试探

结论：**在只放宽 `slashblade` 依赖版本范围的情况下，0.1.2 能在 SlashBlade Resharped
2.0.7-1.21.1 上加载，并通过全部 16 个 GameTest。** 但这是 2.0.7 的服务器侧试验，
客户端渲染没有实测；当前正式目标仍是 2.1.9。

## 唯一硬阻塞

`src/main/resources/META-INF/neoforge.mods.toml` 的 `slashblade` 依赖是精确版本：

```toml
versionRange="[2.1.9-1.21.1]"
```

所以未修改的 0.1.2 会被加载器直接拒绝，根本到不了类加载阶段。

## 静态 API 对比

对 2.0.7 和 2.1.9 的 jar 做了 `javap` 对比，0.1.2 实际用到的类/方法/注入点都存在且签名一致：

- `SlashArts` 构造器、`setComboStateJust`、`setComboStateSuper`、`setProudSoulCost`
- `ComboState.Builder`、`ComboStateRegistry` 的公开成员
- `BladeStateAccess.of`、`ISlashBladeState.getTranslationKey/isBroken/isSealed`
- `SlashBladeDefinition.getBlade(HolderLookup.Provider)`、`getName/getTranslationKey`
- `EntitySlashEffect.tick`、`SuperSlashArts.releaseSSA(ServerPlayer)`
- `InputCommandEvent`、`SlashBladeEvent`、`InputCommand`、`AttackManager`

2.1.9 新增了 `ISlashBladeState.getDefaultSwordTypes/setDefaultSwordTypes`、
`SlashBladeDefinition.getBlade()` 无参重载、`EntitySlashEffect.SLASH_BASE_SIZE_ATTRIBUTE_ID`
等，但 0.1.2 没有调用这些新 API，所以不构成二进制不兼容。

`data/terminalblade/slashblade/named_blades/mistletoe.json` 的字段结构也同时被 2.0.7/2.1.9 接受。

## 实测

方法：

1. 复制测试专服和终端拔刀剑 JAR，只把 `slashblade` 的 `versionRange` 改成 `[2.0.0,2.1.9]`。
2. SlashBlade 从 2.1.9 换成 2.0.7-1.21.1。
3. 启动 NeoForge 21.1.264 专服：Mod List 识别 `Slash Blade:Resharpened 2.0.7-1.21.1` 和
   `槲寄生 0.1.2`，`Done`。
4. 用 `forgeserverdev` + `[2.0.0,2.1.9]` 的类目录跑 GameTest：**16/16 通过**。

日志：

- `docs/artifacts/server-load-2.0.7.log`
- `docs/artifacts/gametest-2.0.7.log`

## 没有覆盖

- **只测了 2.0.7**；2.0.0–2.0.6 没有逐个测。要支持 2.0.x，建议范围至少写
  `[2.0.7-1.21.1,2.1.9-1.21.1]`，而不是整个 2.0.x。
- **客户端渲染没有测**：2.0.7 的模型组、`effect`、GUI、第一/第三人称、收鞘、损坏、
  alpha 贴图都可能和 2.1.9 不同；服务器 GameTest 不覆盖这些。
- **2.1.9 专属行为**：2.0.7 的 `ComboStateRegistry` 内部实现和 2.1.9 不同；虽然 16 个
  GameTest 过了，但不等价于所有边界行为。
- 2.0.7 的 `mrqxs_Slashblade_Core` 在本次专服里没有装，终端拔刀剑仍能加载；
  整合包里其它附属若依赖它，是另一回事。

## 如果要正式支持 2.0.7

1. 把 `gradle.properties` 的
   `slashblade_version_range=[2.1.9-1.21.1]`
   改成包含 2.0.7 的范围，例如
   `[2.0.7-1.21.1,2.1.9-1.21.1]`，重新构建。
2. 在 2.0.7 客户端实测 A-15/A-16，特别看模型组和 `effect`。
3. 保底方案仍是让整合包升级到 2.1.9；2.1.9 才是当前开发和 GameTest 的正式目标。

这次试验没有修改项目代码或依赖范围，只在临时副本里改了元数据。
