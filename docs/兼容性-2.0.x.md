# SlashBlade 2.0.7–2.1.9 兼容性

结论：**0.1.2 现在正式接受 `2.0.7-1.21.1` 到 `2.1.9-1.21.1`。** 2.0.7 和 2.1.9 的专服
加载都通过，两边的 GameTest 都是 17/17。客户端渲染仍未实测；2.1.9 仍是开发和 GameTest 的
主基准。

## 改了什么

`gradle.properties`：

```properties
slashblade_version_range=[2.0.7-1.21.1,2.1.9-1.21.1]
```

构建后的 `META-INF/neoforge.mods.toml` 会写成同一个范围。之前是精确的
`[2.1.9-1.21.1]`，加载器会直接拒绝 2.0.7，根本到不了类加载阶段。

## 静态 API 对比

对 2.0.7 和 2.1.9 的 jar 做了 `javap` 对比，0.1.2 实际用到的类/方法/注入点都存在且签名一致：

- `SlashArts` 构造器、`setComboStateJust`、`setComboStateSuper`、`setProudSoulCost`
- `ComboState.Builder`、`ComboStateRegistry` 的公开成员
- `BladeStateAccess.of`、`ISlashBladeState.getTranslationKey/isBroken/isSealed`
- `SlashBladeDefinition.getBlade(HolderLookup.Provider)`、`getName/getTranslationKey`
- `EntitySlashEffect.tick`、`SuperSlashArts.releaseSSA(ServerPlayer)`
- `InputCommandEvent`、`SlashBladeEvent`、`InputCommand`、`AttackManager`

2.1.9 新增了 `ISlashBladeState.getDefaultSwordTypes/setDefaultSwordTypes`、
`SlashBladeDefinition.getBlade()` 无参重载、`EntitySlashEffect.SLASH_BASE_SIZE_ATTRIBUTE_ID`
等，但 0.1.2 没有调用这些新 API，所以不构成二进制不兼容。

`data/terminalblade/slashblade/named_blades/mistletoe.json` 的字段结构也同时被
2.0.7/2.1.9 接受。

## 实测

环境：NeoForge 21.1.264、MC 1.21.1、Java 21、0.1.2 生产 JAR。

| 项 | SlashBlade 2.0.7 | SlashBlade 2.1.9 |
| --- | --- | --- |
| 专服加载 | `Done` | `Done` |
| GameTest | 17/17 | 17/17 |
| 客户端渲染 | 未测 | 未测 |

日志：

- `docs/artifacts/server-load-2.0.7.log`
- `docs/artifacts/gametest-2.0.7.log`
- `docs/artifacts/server-load-2.1.9.log`
- `docs/artifacts/gametest-2.1.9.log`

2.0.7 的专服只装了 2.0.7 + 槲寄生，没有装 `mrqxs_Slashblade_Core`；终端拔刀剑仍能加载。
整合包里其它附属若依赖 `mrqxs`，是另一回事。

## 没有覆盖

- **2.0.0–2.0.6 没有逐个测**；范围从 2.0.7 开始，旧版本不承诺。
- **客户端渲染没有测**：2.0.7 的模型组、`effect`、GUI、第一/第三人称、收鞘、损坏、
  alpha 贴图都可能和 2.1.9 不同；服务器 GameTest 不覆盖这些。
- **2.1.9 专属行为**：2.0.7 的 `ComboStateRegistry` 内部实现和 2.1.9 不同；虽然 17 个
  GameTest 过了，但不等价于所有边界行为。
- **诊断测试**：同一 300 HP 无护甲目标，平 A 掉血 64，强化 SA 掉血 124.4，施法者献祭后剩 18；
  2.0.7/2.1.9 都通过。实际整合包里若 SA 反而更低，优先查目标最大生命是否 >100、目标护甲/伤害类型、
  以及是否有模组拦截 `mistletoe_slash`。
- 2.0.7 客户端如有渲染差异，优先保持 2.1.9 为正式目标，或把范围收窄回 2.1.9。

## 版本策略

- 2.0.7–2.1.9 都接受；日常开发和 GameTest 仍以 2.1.9 为准。
- 如果 2.0.7 客户端 A-15/A-16 出现模型/渲染问题，先修客户端兼容，不要为了 2.0.7 改战斗逻辑。
- 2.0.0–2.0.6 不在承诺范围内；需要时单独加测试再放范围。
