# 初雪：美术资源交付与接入清单

更新日期：2026-11-09。适用范围：Minecraft 1.21.1 / NeoForge 主工程。

依据：用户提供的《槲寄生_初雪_美术资源制作规格书_v1.0.docx》与当前资源、代码。原规格提供美术方向；本文补充实际加载方式、交付清单和程序接入依赖。建议方案尚未修改游戏资源，也不代表概念参考图已完成制作。

玩法状态与测试要求见 [初雪-玩法功能实现与验收](初雪-玩法功能实现与验收.md)。

## 1. 美术目标与当前状态

沿用系列刀身、刀柄的结构、比例和基础 UV，重点修改刀镡、刀鞘与配色。保留传统打刀轮廓，采用小型雪花/六角刀镡、冷白灰或淡灰蓝刀鞘、冷银配件，以及少量霜化枝叶与白果。

参考配色：银白 `#E8EEF6`、冷灰 `#C9D1DB`、冰蓝 `#A9D8FF`、浅青灰 `#D6E7E5`、雪白 `#F7FBFF`。这些是设计参考，不要求逐像素匹配。概念图不作为尺寸、UV 或可直接导入的贴图。

| 项目 | 当前状态 | 差距 |
|---|---|---|
| 刀体模型 | 初雪引用 `first_snow.obj`，14586 顶点、4862 三角面，13 组 | 已接入；r3 雪花刀镡、收敛刀鞘、立体流苏 |
| 主体贴图 | `first_snow.png`，1024×1024 RGBA，302567 字节 | 已接入；冷色图集，16×16 仍需实机确认 |
| 物品栏 | 使用 OBJ 的 `item_*` 组与主图集；图集中已有菱形装饰 | 没有独立图标 PNG 加载入口 |
| 霜刃刀光 | 本体斩击实体染色 `#DDEFFF` | 没有专属 `frost_slash.png` 加载入口 |
| 霜刃粒子 | 沿用通用花瓣、浆果、闪光 | 未形成独立雪霜粒子方案 |
| 动作 | 本体 400–449 帧、1.6 倍速 | 未制作专属 VMD；原规格也未要求七套动作 |

基准文件：[dawn.obj](../src/main/resources/assets/mistletoe/model/named/dawn.obj)、[first_snow.obj](../src/main/resources/assets/mistletoe/model/named/first_snow.obj)、[first_snow.png](../src/main/resources/assets/mistletoe/model/named/first_snow.png)、[初雪资源绑定](../src/main/resources/data/mistletoe/slashblade/named_blades/first_snow.json)。

## 2. 推荐交付清单

模型和主体图集的游戏路径统一为 `src/main/resources/assets/mistletoe/model/named/`。原规格的 `initial_snow` 为建议名，按工程现有 ID 统一使用 `first_snow`。

| 交付项 | 文件或内容 | 必要性 | 接入说明 |
|---|---|---|---|
| 初雪完整模型 | `first_snow.obj` | 必须 | 从当前朝露模型派生；保留下节分组及变换约定 |
| 主图集 | `first_snow.png`，1024×1024 RGBA | 必须 | 推荐单张图集，含新刀镡、刀鞘和图标所需区域 |
| 模型制作源文件 | 实际建模工具源文件及导出说明 | 建议 | 保留可编辑部件、UV、法线与导出设置 |
| 贴图制作源文件 | 实际绘图工具分层文件及 UV 线框 | 建议 | 标明刀身、柄、镡、鞘、发光与图标区域 |
| 物品栏成品 | `item_*` 组及对应图集区域 | 必须 | 正常、损坏、无鞘状态均需核对 |
| 独立图标稿 | 可命名 `first_snow_icon.png` | 辅助交付 | 可以用于设计/烘焙；不能替代当前游戏加载的分组和图集 |
| 刀镡/刀鞘分层稿 | 可独立保存制作文件 | 按方案 | 游戏成品优先并入主图集；独立 PNG 不能自动绑定 |
| 专属刀光 | `frost_slash.png` | 原规格要求；接入前置条件未完成 | 确定渲染路线后再锁定路径、尺寸、UV 和通道 |
| 预览与验收截图 | `first_snow_preview.png` 或按视角分别保存 | 必须用于最终验收 | 区分离线渲染图与真实游戏截图 |

本仓库当前一把刀只配置一个 `texture`，现有 OBJ 没有 `mtllib/usemtl` 声明。新增独立 UV 不等于能新增一张运行时材质；如果选择多图材质，必须先完成对应程序接入。

## 3. OBJ 导出约定

以当前 `dawn.obj` 为制作基准，保持原点、比例、坐标方向、反り方向、装配关系和现有 UV 朝向。不要重新居中、归一化到单位尺寸或自动翻转 UV 后直接交付。

当前刀体长轴沿 X 轴：`blade` 的 X 边界约为 -286～48，`sheath` 约为 -296～-17。这些数据用于核对现有坐标尺度，不是现实毫米单位，也不是限制新增刀镡的绝对尺寸。

按当前渲染约定保留以下 13 个分组：

```text
blade
blade_luminous
blade_damaged
blade_damaged_luminous
sheath
sheath_luminous
effect
item_blade
item_blade_luminous
item_damaged
item_damaged_luminous
item_bladens
item_bladens_luminous
```

- 制作源文件可用 `handle`、`tsuba` 等部件名，但最终几何要归入被渲染的组，不能指望新增组名自动显示。
- 新刀镡与刀鞘需在相关手持、物品栏和损坏状态中同步处理；不能只改正常手持模型。
- 物品栏组采用独立摆放：当前 `item_blade` 的 X/Y 范围约 -72.07～78.20、Z 约 1.2～4.8，发光层 Z 约 5.4～5.6。保留层次关系，避免重叠闪烁。
- 初雪没有暮色 Super 藤蔓需求，不必复制暮色模型的 `grow_*` / `grow_lum_*` 组。`effect` 是另一套本体充能渲染约定，仍需保留并验收。
- 检查三角化、面朝向、UV 索引、透明边缘和发光分组；完整文件能被 OBJ 查看器打开，不等于能被本体正确渲染。
- 原规格的冷银、霜纹等材质目标优先通过当前图集表达；当前项目未提供独立法线、金属度或粗糙度贴图接入约定。

现有 `tools/gen_assets.py` 是旧占位资源生成器，且路径仍含旧命名空间 `terminalblade`，不应作为正式初雪资源导出工具直接运行覆盖资源。

## 4. 物品栏图标管线

当前图标采用 `item_blade`、`item_damaged`、`item_bladens` 及对应发光组，使用主图集。新交付应在这些组中实现菱形装饰、内部雪霜主题和交叉刀鞘构图。

必须区分两层：

1. 美术装饰背板及刀鞘构图：可通过图集与 OBJ 分组实现。
2. SlashBlade 自身的耐久显示层：项目现有说明指出外侧青紫菱形属于该层，不能默认通过初雪主贴图改色或改形。若需要改变，另列程序接入任务。

独立 `first_snow_icon.png` 可作为整张设计稿，但当前程序不会自动读取它。选择直接绘制整张 PNG 时，需要先增加相应渲染入口，不能只把图片放进资源目录。

验收必须看实际 16×16 物品栏尺寸以及不同 GUI 缩放，重点检查冷白刀体、浅色背景与雪花是否混成一块。大图好看不能替代小尺寸辨识度。

## 5. 霜刃特效管线

当前调用链为 `frostBladeHit → spawnSlash → AttackManager.doSlash`，只调整本体斩击的颜色、roll、尺寸与寿命，没有自定义贴图参数。相关代码见 [MistletoeCombat.java](../src/main/java/dev/xingguang/terminalblade/combat/MistletoeCombat.java)。

现状参数：七段间隔 2 tick；roll 从 -35° 起每段增加 12°；颜色 `#DDEFFF`；尺寸参数 2.4；寿命 8 tick。刀光会发生时间重叠；roll 变化不能当作锥形伤害范围的可视化保证。当前第七刀没有独立收尾特效。

在制作最终刀光前确定以下路线之一：

| 路线 | 美术工作 | 程序工作 |
|---|---|---|
| 沿用本体刀光 | 调整颜色、视觉密度及雪霜粒子方向 | 调整姿态/寿命/大小；如增加专属粒子需注册和调用；须确认是否接受改变原规格的必交 PNG 要求 |
| 专属刀光贴图 | 制作可复用的 `frost_slash.png` | 先确认本体可扩展接口或新增专用渲染实现，再接贴图和时序 |

专属贴图路线在以下事项明确前，不应宣称资源可直接导入：

- [ ] 游戏内资源路径、加载对象及专属效果识别方式。
- [ ] 静态贴图还是序列帧、尺寸、UV、纹理方向和中心点。
- [ ] 透明混合方式、是否发光、颜色是否再乘以实体染色。
- [ ] 七刀位置、方向、寿命、淡入淡出及重叠密度。
- [ ] 第七刀若做视觉强调，只改变视觉参数，不增加伤害调用。
- [ ] 是否替换通用花瓣/浆果粒子；避免全局替换影响暮色和朝露。

不把“一张 PNG”同时当作武器 `effect` 组、斩击实体纹理和普通粒子序列；它们是不同接入点。原规格不要求新增 VMD，当前优先沿用本体动作；若后续制作专属动作，另行约定骨骼和时间线。

## 6. 程序接入清单

- [x] 新模型到位后，将 `first_snow.json` 的 `render.model` 从 `mistletoe:model/named/dawn.obj` 改为 `mistletoe:model/named/first_snow.obj`。
- [x] 确认 `render.texture` 指向初雪图集，所有路径大小写正确。
- [ ] 验证初雪完整分组；当前静态检查已通过，仍需 runClient 看实际渲染。
- [ ] 按选定路线接入刀光与粒子；资源文件存在不等于调用成功。
- [ ] 确认游戏资源已进入构建产物；制作源文件和参考图不要误作运行资源。
- [ ] 保持暮色、朝露资源绑定有效，检查共享资源变更影响。

## 7. 最终验收清单

- [ ] 刀身与刀柄保持系列几何、比例与识别度。
- [ ] 新刀镡具有简洁六角/雪花轮廓；刀鞘为克制的冷白灰/灰蓝与霜化枝叶。
- [ ] 图集、UV、面朝向和透明区域正确；没有缺面、明显穿插或闪烁。
- [ ] 第一人称、第三人称、收刀/背负、掉落及充能状态正常。
- [ ] 正常、损坏、无鞘物品栏分组正确；菱形装饰与耐久显示层不冲突。
- [ ] 16×16 下能分辨刀、鞘、背景和主题；白色区域有足够层次。
- [ ] 真人施放时七道刀光节奏清楚，方向与攻击区域表达一致。
- [ ] 如有末段视觉强调，没有额外伤害或新增状态效果。
- [ ] 多人视角与不同光照下检查可见性、透明效果和粒子密度。
- [ ] 分别保留实际游戏截图与测试记录；服务端测试通过不作为美术验收通过。

当前只完成规格与资源静态对照，尚未完成这份清单中的游戏内美术验收。
