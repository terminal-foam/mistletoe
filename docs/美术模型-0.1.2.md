# 美术模型 0.1.2（合并试验）

分支：`art/v0.1.2`。这次只替换客户端模型/贴图，不改战斗、SA、数据包或注册名。

## 来源

`terminalblade_mistletoe_art_v0.1.2.zip` 的 `dist/`：

- `mistletoe.obj`：13 个 SlashBlade 组，9960 个顶点、3320 个四边形面。
- `mistletoe.png`：512×512 图集，带透明/半透明区域。

`dist` 是 `build_release.py` 归一化后的版本；`demo_model.obj` 里的
`mistletoe_branch` / `mistletoe_leaf` / `mistletoe_berry` 会被 Resharped 的固定组渲染忽略，
所以不能直接拿 `demo_model.obj` 进游戏。

## 本分支验证

- `build-1.21.1.ps1 -Verify`：通过，JAR 271,840 字节，模型/贴图已进 JAR。
- JUnit：11/11 通过（含 `MistletoeModelGroupsTest` 的 13 组检查）。
- GameTest：17/17 通过（`All 17 required tests passed`）。
- 客户端 A-15/A-16：**未执行**；本机没有可用的 `neoformruntime/assets` 和 2.1.9 客户端实例。

## 静态检查

用美术包自带的 `check_ingame.py` 对 `dist/mistletoe.obj` 检查：

- 必需组、同组唯一性、组名合法性、索引越界：通过。
- `blade ⊂ sheath`：通过（最大越界 -0.22，包住）。
- `blade_damaged ⊂ blade`：通过。
- 发光层/effect 在实体外或贴面。
- 物品组跨度 66/58/24，未超出 GUI 视野。

注意：`check_ingame.py` 打印 `✓/✗`，在 Windows GBK 控制台会抛 `UnicodeEncodeError`；
运行时加 `PYTHONIOENCODING=utf-8`，或先把符号改成 ASCII。

## 已知限制

- **枝叶是烘进 `blade` 的静态几何**，普通状态就一直在刀镡附近。当前没有 SA 生长/收回的
  客户端渲染层；0.1.2 不实现这个动画。
- **物品组仍然偏扁**：`item_blade` 的 Z 约 `-1.6..-0.4`，GUI 里从侧面可能像纸片。
- **512 贴图带 alpha**：静态检查不验证渲染层对透明/半透明的处理，必须客户端看。
- **effect 组有 960 个面**，充能效果可能偏重。
- 第一/第三人称、GUI、掉落、损坏、收鞘、充能效果都还没有在客户端实测（A-15/A-16）。

## 生成器保护

`tools/gen_assets.py` 现在默认**不覆盖**已存在的 `mistletoe.obj` / `mistletoe.png`：

- 正常跑：`python tools/gen_assets.py`，保留美术模型，只更新粒子/音效。
- 要恢复旧的占位模型：`python tools/gen_assets.py --force-placeholder`。

## 重新生成

美术包的 `build_release.py --install --repo <项目 assets/terminalblade>` 可重新安装 `dist`；
默认是 dry-run，`--install` 才会写入，并给旧文件生成 `.bak`。
