# 0.1.2 实现决策（对计划 v1.0 的收敛）

基线：`v0.1.1`（tag `v0.1.1`，源码/资源与 0.1.1 发行 jar 一致）。

本文件记录 0.1.2 实现前对《下一阶段开发计划与技术路线 v1.0》的必要收敛。计划里没有写死、或前后不一致的地方，以本文件为准；本文件不改变第 1 节已确认的数值（100 HP 阈值、10%/20%、90%、半径 8、生命不足仍发动）。

## 1. Super SA 处决顺序（取代计划第 3 节）

计划 M1-01 与第 3 节对“阶段锁血检查”的位置相反。0.1.2 统一为：

1. 目标筛选（沿用 `MistletoeTargets`，排除默认玩家/宠物等）。
2. 对每个目标查询 `PhaseLockResolver`：
   - 动态适配器优先；没有动态答案时才看静态保护标签。
   - `LOCKED`：**不施加 Super SA 伤害，也不强制处决**，记录 `phase_locked`。
   - `UNLOCKED` / `UNKNOWN`：继续。
3. 用 `mistletoe_godslayer_absolute` 打正常伤害（`bypasses_invulnerability`）。
4. 若目标 `isRemoved()` 为 true：正常死亡，结束。
5. 若目标仍在（包括生命为 0 但 `LivingDeathEvent` 被取消的情况）：**再次查询阶段锁血**；仍为 `LOCKED` 则不强制处决。
6. 强制处决：`setHealth(0)` + `entity.die(source)`，作用域内用 LOWEST + `receiveCanceled` 解除死亡取消；只对当前强制目标生效。
7. 所有目标处理完后，再献祭施法者 90% 最大生命。

关键点：`bypasses_invulnerability` 的伤害**绝不能在已识别为阶段锁血的目标身上先打出去**，否则 Boss 可能在检查锁血之前就被打死，“阶段锁血允许保留”就不成立。

## 2. 已确认规则对 0.1.1 的覆盖

- Super SA 默认穿透实体无敌标签：删除 `super_slash_art.bypass_invulnerability` 配置；未锁血目标固定使用 `mistletoe_godslayer_absolute`。
- Super SA 不接受普通脚本取消死亡作为保护：删除 `super_slash_art.finish_unyielding` 配置；改为作用域强制处决。
- `mistletoe_godslayer`（不带无敌穿透）保留，用于伤害类型标签/将来“锁血目标是否允许正常伤害”的显式分支；0.1.2 对锁血目标选择完全跳过伤害。
- 旧 D-02、D-03 由本节取代。D 编号保持 0.1.1 的编号，不重新编号；耐久附魔新增为 **D-09**。

## 4. 阶段锁血接口

- `PhaseLockStatus`：`LOCKED` / `UNLOCKED` / `UNKNOWN` 三态，避免 boolean 把“未适配”当成“未锁血”。
- `PhaseLockAdapter`：第三方模组在公共初始化时调用 `PhaseLockResolvers.register(...)`；同一目标只要有一个适配器返回 `LOCKED`，即视为锁血。
- 静态保护标签：`terminalblade:super_sa_phase_protected`（实体类型）。默认空。
  - 只作为**未适配** Boss 的保守兜底；动态适配器返回 `UNLOCKED` 时不被静态标签覆盖。
  - 不复用 `super_sa_exclude`（后者是“完全排除出球范围”，不是“允许正常伤害、禁止强制处决”）。
- `UNKNOWN` 的默认行为：按普通实体处理（可正常伤害、可强制处决），需要保护的整合包请加保护标签。文档不得声称能自动识别未知 Boss 的阶段锁血。

## 5. 处决成功判定（GameTest 首轮失败后修正）

1.21.1 的 `LivingEntity.die()` 不会立刻移除实体：它设置 `dead=true`、进入 `Pose.DYING`，`tickDeath()` 20 tick 后才 `remove(KILLED)`。因此：

- **不能用 `isRemoved()` 判断“已经处决”**；正常死亡和强制处决都会短暂处于 `health=0 && !isRemoved()`。
- 正常伤害后的判断改为 `isDeadOrDying()`（health <= 0）→ `KILLED_BY_DAMAGE`，不再对垂死目标重复强制处决。
- 强制处决的返回改为 `isRemoved() || isDeadOrDying()`。
- 如果目标模组在 `LivingDeathEvent` 里把生命治疗回来，`die()` 的死亡逻辑已经跑完但目标还活着；强制处决在 `die()` 返回后把生命再压回 0，让原版进入 DYING/tickDeath。
- 测试 T-03 的“死亡拦截”必须同时取消事件并回血，才等价于真实的复活脚本；只取消不回血时目标会停在 0 血被 tickDeath 正常移除，测不出强制处决。T-03 另加 LOWEST 观察者，确认模组确实把死亡取消解除，而不是只靠事后压血。
- T-11 改用僵尸施法者：SlashBlade 对 `makeMockServerPlayerInLevel()` 发 `slashblade:motion_broadcast` 包会抛异常，与耐久逻辑无关。
